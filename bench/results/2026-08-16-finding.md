# WebAssembly benchmark finding — 2026-08-16

## Result

WebAssembly was **5.682x faster in Chrome** and **7.982x faster in Firefox**
than the tuned JavaScript worker by median hashes per second. This clearly
looks material. The owner still decides what “material” means and makes the
engine choice.

| Browser | Rust/WASM median | WASM spread (min–max; p25–p75) | JavaScript median | JS spread (min–max; p25–p75) | WASM / JS | WASM cold start |
|---|---:|---:|---:|---:|---:|---:|
| Google Chrome 151.0.7922.138 | 1,849,112 H/s | 1,438,435–1,906,941; 1,842,299–1,872,659 | 325,436 H/s | 313,952–329,164; 318,959–326,413 | 5.682x | 14.3 ms |
| Mozilla Firefox 138.0.1 | 1,479,290 H/s | 1,275,510–1,552,795; 1,308,901–1,524,390 | 185,322 H/s | 174,459–203,749; 179,986–188,395 | 7.982x | 46.0 ms |

The generated WebAssembly module is 23,419 bytes (22.87 KiB). Both measured
browsers ran the benchmark inside an actual Web Worker served from localhost.

Safari 26.5.2 was installed but was not measured. SafariDriver refused to
create a session because **Allow remote automation** is disabled in Safari
Settings. The runner records this as skipped. It does not fabricate a Safari
number.

## Correctness gate

The runner checked four shared vectors before taking a timing sample. The
Rust/WASM digest and the tuned JavaScript digest both equalled these native
`bproof verify --json` outputs:

| Vector | Digest |
|---|---|
| small mining nonce | `0xe0728a02790ebf24be70574538af0f2e326940edc70ae1114a464f9e9adbb6d1` |
| maximum mining nonce | `0x2d283617f3625a1cb8890a4287050a6ad9e51eb33e98174df059c8a6cf9923f6` |
| zero address and mining nonce | `0x68d30e5336eeaed0191320852c02a7f058bff050aafccd64c119a260704b6909` |
| 32-bit boundary | `0x5f8bb979059f5a69e68eb1ed3fb184c7ce8e59f3752c073946dd3e4de283b70d` |

All nine timed nonce ranges in both browsers also had equal cross-engine
checksums. Timing cannot start if the four digest vectors disagree.

## Method and machine

- Date: 2026-08-16 Australia/Sydney.
- Machine: Mac14,10; Apple M2 Pro; 12 logical CPUs; 16 GiB memory; macOS
  26.5.2.
- Samples: nine runs per engine and browser; 250,000 hashes per run; 50,000
  warmup hashes; alternating engine order.
- Rust path: release build with `opt-level=3`, LTO, one codegen unit and aborting
  panics. The adapter calls `proof_core::proof_digest` and
  `proof_core::meets_target` for every attempt.
- JavaScript path: Noble's 32-bit Keccak permutation, one constant block
  pre-absorbed, reusable typed arrays, fixed tail absorption, in-place mining
  nonce increment, and no allocation per attempt.
- Raw measurements: [2026-08-16-apple-m2-pro.json](2026-08-16-apple-m2-pro.json).
